# Structured validation for AI agent fleets: doctrine and the emerging landscape

**The "doctrine" project by Amir Elaguizy appears to address a genuine gap in multi-agent AI governance: schema-based validation and drift detection for the structured documents (SOUL.md, AGENTS.md, IDENTITY.md, MEMORY.md) that define agent behavior across a fleet.** While the repository at github.com/aelaguiz/doctrine is private and could not be directly inspected, contextual evidence — Elaguizy's public writing about managing Claude Code agents "like a CTO manages developers," his declarative prompting framework langdspy, and his multi-agent orchestration work with OpenClaw/PokerSkill — strongly suggests doctrine is a validation and consistency enforcement layer for agent configuration documents. This concept sits at a critical intersection where no single existing tool fully delivers: combining structured document validation, schema enforcement, and fleet-wide drift detection for the markdown-based identity files that increasingly define how AI agents behave.

The landscape is moving fast. **Over 30 open-source projects, 28 academic papers, and dozens of commercial platforms** now touch some aspect of this problem — but the space remains fragmented, with most tools solving only one slice of the full challenge.

## The doctrine concept and why the gap matters

The term "doctrine" — a body of principles held by a group — maps precisely to the emerging pattern of governing AI agent behavior through structured configuration documents. In military usage, doctrine provides consistent behavioral guidelines across units; in multi-agent AI systems, files like SOUL.md (identity and personality), RULES.md (hard constraints), MEMORY.md (persistent context), and AGENTS.md (coordination instructions) serve the same function.

Elaguizy's public philosophy reinforces this interpretation. In LinkedIn posts, he describes managing AI agents through structured workflows: GitHub epics broken into discrete tasks with acceptance criteria, comprehensive planning phases, and "stable context" as a management principle. His langdspy project ("declarative prompting compatible with langchain, scikit-learn — enterprise ready") demonstrates a pattern of treating agent instructions as first-class, validatable artifacts rather than ad-hoc text. **Doctrine likely extends this philosophy from individual prompts to fleet-wide behavioral specifications** — ensuring that when you define how an agent should behave, that definition conforms to a schema, remains consistent across deployments, and triggers alerts when drift occurs.

The need is well-documented academically. A January 2026 paper by Abhishek Rath formally defined "agent drift" and demonstrated that unchecked drift causes a **~42% reduction in task success rates** and a **5x increase in inter-agent conflicts**. Anthropic-affiliated research showed that even well-specified agent goals drift after 100,000+ tokens of interaction. IBM Research found that silent failures in multi-agent trajectories can be detected with up to 98% accuracy using supervised methods — but only if you have a specification to validate against.

## Closest open-source matches form a fragmented ecosystem

The single closest project to doctrine is **gitagent** (github.com/open-gitagent/gitagent), a framework-agnostic, git-native standard for defining AI agents. It uses the exact same file conventions — `agent.yaml` manifest, `SOUL.md`, `RULES.md`, `DUTIES.md`, `AGENTS.md`, `MEMORY.md` — and includes a `gitagent validate` command that checks definitions against JSON schemas on every push via GitHub Actions. It supports segregation of duties enforcement (maker/checker/executor/auditor roles with a conflict matrix), compliance sections for regulated environments (FINRA, SEC, EU AI Act), and agent composition through `extends:` and `dependencies:` fields. With ~1,000 stars and active development in 2026, it represents the most complete open-source implementation of configuration-level agent governance. However, it lacks explicit fleet-wide drift detection — relying instead on git diff/blame for change tracking.

**Microsoft's Agent Governance Toolkit**, released April 2, 2026 under MIT license, is the most mature governance framework overall but focuses on runtime policy enforcement rather than configuration document validation. Its seven-package architecture includes a stateless policy engine (sub-0.1ms latency) supporting YAML rules, OPA Rego, and Cedar policies; a trust mesh with Ed25519 cryptographic identity and trust scoring on a 0–1000 scale; and automated compliance verification mapping to EU AI Act, HIPAA, and SOC2. With **285+ stars and 9,500+ tests**, it integrates with LangChain, CrewAI, AutoGen, Google ADK, and OpenAI Agents SDK. It addresses OWASP's Agentic Top 10 risks comprehensively but does not validate the structured markdown documents that define agent identity.

Several agent configuration synchronization tools address the "single source of truth" problem without full validation:

- **ai-rulez** generates synchronized instructions for 18+ tools (Claude, Cursor, Copilot, Windsurf) from a single config, with remote includes for team/company standards and profile systems for different teams
- **Ruler** distributes rules from a centralized `.ruler/` directory to 30+ agent tools with auto-configuration propagation
- **rulesync** and **ai-rules-sync** use symlink-based and git-based approaches respectively to prevent configuration drift between agent tools

On the specification side, **Oracle's Agent Spec** provides a declarative YAML/JSON language with a Python SDK for building, validating, and transforming agent definitions. **Agent-Flavored Markdown** (WSO2, published at ACM IUI 2026) cleanly separates natural language instructions from YAML configuration. The **Open Agent Format** uses a single AGENTS.md file with YAML frontmatter as a universal agent specification. None of these combine specification with drift detection.

## Academic research reveals a rapidly maturing field

The academic landscape divides into five distinct streams, all converging on the problem doctrine appears to address.

**Drift detection** has become a first-class research concern. Beyond Rath's foundational 2026 taxonomy (defining semantic drift, coordination drift, and behavioral drift with a 12-dimension Agent Stability Index), the RIVA system demonstrates multi-agent cross-validation for configuration drift detection — recovering accuracy from 27.3% to 50.0% on the AIOpsLab benchmark by having agents verify each other's findings. Anthropic-affiliated work on goal drift shows that environmental pressures cause agents to deviate from their system-prompt-specified objectives, with even the best models (scaffolded Claude 3.5 Sonnet) exhibiting measurable drift after extended interactions. This directly motivates the need for continuous validation of agent configurations against behavioral specifications.

**Governance-as-infrastructure** frameworks are proliferating. The Governance-as-a-Service (GaaS) paper proposes a modular, policy-driven enforcement layer using declarative JSON rules and a Trust Factor mechanism that scores agents based on compliance history. MI9 combines six coordinated mechanisms including goal-conditioned drift detection and finite-state conformance engines. The Policy Compiler for Secure Agentic Systems (PCAS) achieves **1.68–2.93x improvement over frontier LLMs** in policy compliance by expressing policies in a Datalog-derived language with deterministic enforcement.

**Formal specification approaches** are being adapted for agent systems. AgentSpec (ICSE 2026) introduces a domain-specific language for specifying safety rules as formal three-tuples — a triggering event, predicates, and enforcement functions. SEMAP adapts Design by Contract principles from software engineering: explicit behavioral contracts with verifiable input/output schemas, achieving up to **69.6% reduction in failures**. Agent Contracts formalizes lifecycle states (proposed → active → completed/failed) with guard conditions and resource budgets.

**Constitutional and normative approaches** extend beyond Anthropic's foundational Constitutional AI. Multi-Agent Constitution Learning (MAC, March 2026) optimizes governance rules using networks of agents that accept, edit, or reject rule updates. Constitutional Evolution discovers behavioral norms through LLM-driven genetic programming, with evolved constitutions significantly outperforming both adversarial (total collapse, stability score S=0) and vague principles (S=0.249). Research on normative multi-agent systems for software engineering teams provides theoretical grounding for regulating agent interactions through explicit norms determining permitted, prohibited, and obligatory behaviors.

## Industry is racing to build the agent governance control plane

The commercial landscape reveals an emerging category that Gartner has named the **Agent Management Platform (AMP)**, predicting **$15 billion in spending by 2029** — a 3,000x growth from current levels. The comparison is telling: "Deploying AI agents without an Agent Management Platform is like driving a car with no brakes."

Dedicated governance startups include **Credo AI** (Forrester Wave Leader, Fast Company #6 Most Innovative 2026), which provides continuous governance across agent ecosystems from pre-deployment to runtime with automated policy enforcement for EU AI Act and NIST AI RMF. **Geordie AI** won RSAC 2026's Innovation Sandbox for behavioral observability across agent fleets. **Zenity** offers security posture management that correlates configuration, permissions, and runtime behavior. **Astrix Security** pioneers identity-first agent governance, noting that non-human identities (agents, service accounts, API keys) **outnumber humans 100:1** in some enterprises.

Every major cloud provider now offers agent governance capabilities. AWS Bedrock provides prompt versioning with drift detection through periodic validation on golden test cases and shadow mode deployment. Google's Vertex AI Agent Builder includes deterministic guardrails and centralized governance. Microsoft offers three layers: the open-source Agent Governance Toolkit, the commercial Agent 365 control plane, and Cloud Adoption Framework guidance for agent fleet governance.

The OWASP Top 10 for Agentic Applications, published December 2025 and peer-reviewed by 100+ experts, established the first formal taxonomy of agent security risks — from goal hijacking and tool misuse to cascading failures and rogue agents. Its foundational defense principle, the **"Principle of Least Agency,"** mandates minimum autonomy, tool access, and credential scope for each agent.

## Adjacent infrastructure patterns are converging on agent governance

The most significant convergence comes from **policy-as-code tools**. Open Policy Agent (OPA) — a CNCF-graduated project used by Netflix, Goldman Sachs, and Google Cloud — is being adapted as middleware between AI agents and their tools, with Rego policies evaluating every tool call before execution. CodiLime built a production system using OPA for MCP-connected agents controlling live network infrastructure, implementing three authorization layers (tool access, device access, command authorization) in a single query. The YAML-OPA-LLM-Guardrails project compiles human-readable YAML guardrail definitions into OPA bundles, bridging the gap between accessibility and enforcement rigor.

**Agent specification standards are crystallizing** under Linux Foundation governance. The Agentic AI Foundation (AAIF), co-founded by Anthropic, OpenAI, and Block in December 2025 with support from Google, Microsoft, and AWS, houses three foundational standards: Anthropic's Model Context Protocol (MCP, **10,000+ active servers, 97 million monthly SDK downloads**), OpenAI's AGENTS.md format, and Block's Goose framework. Google's Agent2Agent (A2A) protocol provides agent-to-agent communication with Agent Cards for capability discovery. AGNTCY's Open Agentic Schema Framework (OASF) provides standardized schemas with built-in validation for agent metadata and capabilities. Oracle's Agent Spec offers a declarative YAML/JSON definition language with cross-framework portability.

Critically, **validation gaps in these standards are well-identified but unfilled**. Security analysis by Semgrep found that A2A's Agent Card signing is supported but not enforced (spoofing risk), MCP doesn't enforce security at the protocol level, and OAuth scopes in A2A are too coarse-grained. These gaps represent precisely where structured validation layers like doctrine would add value.

Formal verification methods are also being applied. The solver-aided verification approach uses Z3 SMT solvers to enforce tool-use policy compliance by translating natural-language policies into formal logic constraints. A theoretical framework for "Runtime Governance: Policies on Paths" proves that prompting is not a true policy function (it modifies probability distributions without evaluating them) — only deterministic runtime evaluation over execution paths qualifies.

## Conclusion: doctrine targets a genuine structural gap

The landscape reveals a paradox: enormous investment in agent governance at the runtime, identity, and policy layers, but **remarkably little work on validating the foundational documents that define agent behavior in the first place**. Most governance tools assume agent specifications are correct and focus on enforcing them at runtime. Most specification standards define formats but don't validate content or detect drift. Most synchronization tools distribute configurations but don't check them against schemas.

Doctrine, as inferred from context, appears to target this specific gap — treating SOUL.md, AGENTS.md, IDENTITY.md, and MEMORY.md as structured, schema-validated, drift-monitored artifacts rather than free-form text. The closest existing tool, gitagent, validates agent definitions against JSON schemas but lacks fleet-wide drift detection. Microsoft's Agent Governance Toolkit provides comprehensive runtime governance but doesn't address configuration document validation. The academic literature establishes that agent drift is real, measurable, and damaging (42% task success reduction) — but no existing tool combines structured document validation with continuous drift monitoring across deployed agent fleets.

Three developments to watch: the convergence of OPA/Rego as a policy engine for agent tool calls (extending naturally to configuration validation); the crystallization of agent specification standards under Linux Foundation governance (providing the schemas to validate against); and the formalization of agent drift as a measurable phenomenon (providing the theoretical foundation for what to detect). Whoever integrates these three threads — specification schemas, policy-as-code validation, and behavioral drift detection — into a unified tool for managing agent fleet doctrine will address a need that the market has identified but no single project yet fully serves.
